# MyMind Features

Version: 15.0.0  
Last Updated: 2026-08-20T00:00:00Z

> **Note:** The canonical version number lives in `package.json` (`version` field). The value above is free text kept in sync manually; if the two disagree, `package.json` is the source of truth. The sidebar version tag is injected at build time from `package.json` via Vite's `define`.

## 1. MyMind visual idea board

MyMind provides a freeform visual canvas for organizing ideas as movable note cards. Each item supports a title, tags, markdown description, optional due date, creation timestamp, canvas position, nullable persisted width and height values, a nullable persisted scale value (real; NULL = 1.0) that grows or shrinks card typography proportionally, and a persisted style tier stored in the existing color field. Cards can be created from the New item button or by double-clicking an empty area of the canvas. Cards can be repositioned by dragging only the small grab dot at the top-left above the title; the rest of each card remains available for selection and editing. The dot selects the card through the normal canvas interaction, respects the canvas selection behavior, and does not open title editing. The board supports zooming, panning, a dotted background, controls, and a minimap.

Cards can be connected by dragging between their edges. Connections use curved floating edges that attach to the nearest point on each card and include a light arrowhead indicating direction. A connection may have an optional detached comment pill. Comment pills can be moved independently of the edge, edited inline, reversed, or deleted from the connection menu. The offset from the edge midpoint is preserved so callouts remain readable as the board changes. Running Tidy recomputes every comment-pill offset against the newly positioned cards and against other pills, choosing the first free candidate from the shared offset search. The card positions and recalculated pill offsets are stored in one undo entry and saved with the next board sync. An Arrange auto-layout command provides a left-to-right hierarchical layout using dagre (rankdir LR, nodesep 48, ranksep 96). Arrange uses each card's real persisted width and height (or the 240px / 92px defaults when NULL) so resized cards space correctly. Dagre returns centre coordinates, which are converted to top-left before applying. Connections whose source or target no longer exists are skipped. When a selection is passed, Arrange lays out only those items using only connections where both endpoints are in the selection, then translates the result so its bounding-box top-left matches the selection's pre-layout bounding-box top-left, keeping the group where it was on the canvas. With no selection, Arrange lays out all items on the active map. The whole operation is one undo entry and the new positions persist with the next board sync.

The board header includes tag filtering. Selecting a tag dims cards and connections that do not match while keeping matching content prominent. A selected card is visually unmistakable without changing its layout box: it uses a 2px indigo ring with zero offset, a soft indigo outer shadow plus the existing card shadow, and a 1.02 scale from the center. The ring, shadow, and scale transition over 120ms. A non-selected hovered card receives only a slightly stronger shadow, with no ring or scale. Selection remains single-card, clears with Escape, and clears when the empty canvas is clicked; because the emphasis uses rings, shadows, and transform rather than borders or padding, connected floating edges retain their routes. A new board starts with no cards and displays the message "Double-click anywhere to create your first card." on the canvas. Double-clicking any empty canvas area creates the first card and starts title editing. The empty board is also a valid loaded state: when the database returns zero item rows, the local board is explicitly replaced with empty items and connections rather than retaining stale local content.

## 2. Canvas zoom and connection reliability

The canvas loads with a maximum fit-to-view zoom of 1 and 20% padding, preventing small boards from opening overly enlarged. Users can zoom between 0.2 and 1.5. The zoom in, zoom out, and fit-view controls sit at the bottom-left of the canvas, while the pannable and zoomable minimap sits at the bottom-right. They occupy separate corners so the controls never overlap the minimap. Both overlays sit above the canvas content and below the sidebar and header layers, and the controls remain visible because the React Flow canvas is inset by the expanded sidebar's 240px width. Fit-to-view content is therefore centered in the usable area rather than underneath the sidebar. Floating connections use the runtime position values required by React Flow, so edges calculate their attachment points without a runtime reference error. Edge types and node event handlers are typechecked as part of the production build. Canvas drag rendering is controlled locally so React Flow can apply position changes without being overwritten by the persistent board model during the gesture. Node and edge type maps, viewport options, grid settings, and other React Flow configuration values use stable identities to prevent unnecessary remounts. Card positions are saved only when dragging stops, while comment-pill movement remains local until pointer-up so leader lines can update without persistent-store writes on every pointer event.

When a connection is completed by dragging from one card to another, an inline comment input appears at the midpoint of the new edge in screen coordinates, focused and ready to type. The input is a single-line text field roughly 220px wide with a placeholder reading "Add a comment…". Pressing Enter commits the comment and closes the input; Escape closes it and leaves the comment empty, in which case the connection still exists but renders no comment pill. Clicking anywhere else on the canvas commits whatever has been typed and closes the input. If the computed midpoint would fall outside the visible viewport, the input is centered in the viewport instead. The input sits above all cards in z-order, carries the nodrag and nopan classes, and stops propagation on key events so typing does not trigger React Flow shortcuts or pan the canvas. After commit, the comment renders as the normal draggable pill offset from the edge by the default label_dx / label_dy. A thin dotted leader line (1px, #cbd5e1, dash pattern 2 3) connects the pill back to the edge, anchored at the midpoint of the visible bezier curve computed via getPointAtLength, with a small 3px filled dot at the anchor point. The line terminates at the nearest edge of the pill's bounding box so it stops cleanly at the pill border. The leader line and dot inherit the same opacity as the edge when tag filtering dims it, sit behind the pill but above card nodes in z-order, and are hidden when label_dx / label_dy are near zero so they do not clutter the curve when the pill sits on top of it. Comment pills render above card nodes even when their saved offsets do not change. The shared React Flow edge-label layer is explicitly stacked above card nodes so the pill and its leader remain visible. The leader line recomputes locally on every pointer move, so it tracks the pill in real time without writing to the persistent board store. The comment pill position is committed once on pointer-up, and after a hard refresh a dragged pill returns to its dragged position rather than the default offset.

The canvas uses a consistent grab cursor across card bodies and connection handles. Each card renders four source handles and four ghost target handles at the same edge positions. Both handle classes use the same 14px by 14px dimensions, crosshair cursor, and active pointer hit area, so moving across an overlapping source or target hit area does not change the pointer or visible interaction state. Ghost handles remain visually transparent and differ from source handles only by z-order. Connection hit areas keep the default cursor, and decorative leader lines and anchor dots do not receive pointer events.

## 3. Viewport persistence

The canvas viewport (x, y, and zoom) is saved to localStorage on move end, debounced to 300ms, and is keyed per map as "mymind.viewport.{mapId}". This is per-device UI state and is not stored in the database. When switching to a map that has a saved viewport, it is restored immediately. When switching to a map with no saved viewport, the canvas resets to the origin and then runs fitView with maxZoom 1 and 20% padding once items are loaded, so the first view of a map is always framed correctly instead of inheriting the previous map's camera. A "Fit to view" button in the top bar lets the user deliberately re-frame the whole board. Viewport restore does not create an undo entry because viewport state lives in localStorage, not the store. Creating the connection and setting its comment is a single logical operation: the connection is created once and the comment is written to that same connection, so there is no duplicate creation.

## 4. Compact cards

Each card defaults to 240px wide and supports five persisted visual style tiers using the existing item color field. Normal cards retain a white surface, a 4px indigo left stripe (#7F77DD), medium-weight 13px title, and gray description. Highlighted cards retain the same title and description weights while using a teal 4px left stripe (#1D9E75) and a subtle horizontal teal-to-transparent body tint that fades toward the right without obscuring description text. Muted cards use the surface-1 background, a neutral-gray 4px stripe, a 0.5px dashed border, a normal-weight secondary-gray title, and a lighter-gray description. Red cards use a #DC2626 stripe with a subtle red horizontal tint, medium-weight dark title, and gray description. Black cards use a #111827 stripe with a subtle charcoal horizontal tint, semibold dark title, and gray description. Muted styling never uses opacity, so cards remain legible when tag filtering dims them. Null or unrecognized stored values are rendered as normal, so older cards require no migration. The card's default width remains 240px across all tiers. Each card may have a persisted integer width from 180px through 700px and height from 92px through 800px; NULL uses the corresponding default so existing rows continue to work unchanged. A selected card shows right-edge, bottom-edge, and bottom-right corner resize handles. Resizing does not change snap-to-grid spacing.

## 4b. Status markers

Each card has an optional status marker stored as a nullable `status` text column on the items table. NULL means no status. The allowed values are "todo", "done", "question", and "important" — the plain enum string is stored, not an emoji or icon name, so the field can be filtered on later. Status is independent of item.color: a red card can also be Done, a black card can also be Question, and so on. Existing rows are unaffected because the column is nullable and defaults to NULL.

The status renders as a 14px icon in the top-right corner of the card, positioned 6px from the top and 8px from the right edge — mirroring the grab dot's 6px-from-top / 8px-from-left placement so the two top corners look balanced. It is always visible — not gated on selection — and scales with the card's typography via the `--card-scale` CSS variable like every other card text element. The icons are: CircleDot (indigo-500, #6366f1) for todo, CheckCircle2 (emerald-600) for done, HelpCircle (amber-500) for question, and AlertCircle (red-600) for important. Each icon has a title and aria-label with the status name. The icon is pointer-events: none so it never intercepts clicks, overlaps the connection handles, or interferes with the NodeResizer.

Status is set through the keyboard or the card context menu. Alt+6 marks all selected cards as todo, Alt+7 as done, Alt+8 as question, Alt+9 as important, and Alt+Shift+0 clears the status. These shortcuts apply to every selected card — the same multi-selection that align, distribute, and multi-delete use — and the whole multi-card change is one zundo history entry and one batched Supabase write. Alt+1-5 and Alt+0 (colour) are unchanged. The card context menu has a Status submenu matching the Style submenu's layout, with the four statuses (each showing its icon, label, and shortcut hint) and a Clear entry (Alt+Shift+0). The shortcuts modal includes a Status section listing Alt+6-9 and Alt+Shift+0.

Each card uses its saved width, or 240px when width is NULL, and has a compact visual layout. A 14px muted-gray grab dot sits 8px from the left edge and 6px from the top edge of the card, above the title row; it darkens on hover and changes from grab to grabbing while dragging. React Flow accepts drag gestures only from this dot, while the dot's double-click event is isolated from inline title editing and ordinary dot clicks continue through to node selection. The card shows the title on one line, a rendered Markdown description preview that fills the available card height and clips at the bottom edge, and a compact row with up to two tag chips, a "+N" indicator for additional tags, and the due-date badge on the right when a due date is set. Card previews use a compact scale: h1 is 14px semibold, h2 is 13px semibold, h3-h6 are 12px semibold, paragraphs are 12px, lists are 12px with 14px left padding, and inline code is 11px monospace. Headings have no border. The title and preview both wrap long unbroken strings such as URLs instead of overflowing. The description preview is omitted entirely when the description is empty, so cards without one stay short. The due-date badge is red when overdue, amber when due within three days, and neutral grey otherwise. A centered "•••" button on the bottom edge opens the floating card editor. Clicking the card body selects it for direct canvas interaction, while double-clicking opens the floating editor.

## 5. Inline editing

Title editing: single-clicking the title text turns it into an input in place, styled identically to the static text so there is no visual jump. Enter or blur commits the change; Escape reverts it. Every creation path — the "+ New item" button, the N keyboard shortcut, double-clicking empty canvas, and Duplicate from the card context menu — starts the new card with the title already in edit mode and the entire "Untitled" (or copied) text selected, so typing immediately replaces the placeholder. The new card is also selected, so pressing Escape to leave the editor leaves the card selected rather than deselected. Enter commits the typed title and leaves the card selected; Escape reverts any typed text to the original title and leaves the card in place — it never deletes the card. The inline editor re-asserts the full-text selection on mount, on the next animation frame, and on the next macrotask so the selection survives the trailing mouseup of a double-click. Clicking a description preview opens an auto-growing inline textarea; it grows with content up to 300px, then scrolls internally. Blur commits the markdown, Escape reverts it, and Enter inserts a newline. The card height changes while typing and edge layout is throttled to animation frames so connections follow without excessive recalculation.

Selected cards expose right-edge, bottom-edge, and bottom-right corner resize handles. Width ranges from 180px to 700px and height ranges from 92px to 800px. During a drag, width and height change locally for smooth feedback; Supabase receives both final dimensions together only when the drag ends, and the complete resize is one undo step. The rendered Markdown description uses the available card height and clips only content that falls below the card boundary, so resized cards reveal more content without growing automatically. Double-clicking the bottom resize handle sets the card height to fit its content exactly: the handler temporarily neutralizes the description container's flex sizing (`flex: 0 0 auto`) and unclamps it (`height: auto`, `max-height: none`, `overflow: visible`), reads its natural scrollHeight, restores every previous inline style synchronously, then computes the new height as the card's fixed header height plus the measured content height plus vertical padding, clamped to 92px–800px and rounded to an integer. The listener attaches to every visible bottom-edge handle matching `.item-node-resizer-handle.bottom:not(.left)`, including the bottom-right handle, while the hidden bottom-left handle is excluded. The double-click is stopPropagation'd so it does not trigger node selection or the inline editor, width is unchanged, and the result is applied through the same commitResize path as a drag (one Supabase write, one undo entry). This is a one-shot fit — editing the description afterwards does not resize the card. The canvas-level onNodeDoubleClick handler inspects the event target and bails out (returns early without opening the popup editor) when the double-click originated inside a resizer handle, checking both the custom `.item-node-resizer-handle` class and React Flow's own `.react-flow__resize-control` class so the fit-to-content handler runs regardless of which element receives the event.

Double-clicking a card opens a 360px floating editor outside the canvas transform, so it remains readable at any zoom level. The editor is anchored beside the card and flips sides near the viewport edge. It contains title, tag, due date, markdown description, a live rendered Markdown preview toggle, and muted created-date text. The edit view remains a plain textarea containing the raw markdown source. Escape or clicking outside closes it. All edits write to the same board state as inline editing. Markdown rendering does not enable raw HTML, so pasted web content cannot inject HTML into card previews.

Inline title and description editing is disabled below 0.6 zoom; clicking a card at lower zoom opens the floating editor instead, since text is unreadable at that scale. Text fields, the popup, and menus carry nodrag and nopan and stop key propagation so typing never triggers canvas deletion or movement.

## 6. Data and editing

The board store owns items and connections and updates cards immediately as users edit, move, or resize them. Resize frames update local state only; the final width and height are committed together to history and persistence once per completed drag. Cards provide a context menu with Edit, Duplicate, and Delete; deleting a card explicitly deletes the card and all of its connections from Supabase before removing them from the local board. Connections are managed directly on the canvas: endpoints can be reconnected to other cards, selected edges can be deleted with Delete or Backspace when no text field is focused, and right-clicking an edge retains its comment, reverse, and delete actions. The Delete and Backspace keys are context-sensitive: when a connection is selected and no cards are selected, the selected connection is deleted; when one or more cards are selected, those cards (and their attached connections) are deleted; when nothing is selected, nothing happens. The shortcuts modal labels this binding "Delete selection" to reflect that it covers both cards and connections. Keyboard focus is tracked for cards separately from connection selection so Escape can clear either selection and Enter can begin editing the selected card title. Every connection exposes one 18px × delete button centered on the visible Bézier curve at its true path midpoint, calculated with getPointAtLength(length / 2). The white button has a 1px slate-300 border and slate-500 glyph, fades in over 120ms while the line, its 20px interaction band, or the button is hovered, remains visible when selected, and turns red with a 1.1 scale on hover. Connections do not render a separate empty-comment dot. The midpoint button, right-click menu, and keyboard delete path each explicitly delete the selected connection from Supabase before removing it from local state; database failures are logged and shown in a toast. Cmd+Z restores the complete connection with its comment text and label offsets, and the next upsert restores the database row. Clicking the edge line still selects it with its existing highlight; the midpoint × is an additional path. Hovering a card thickens and brightens connected edges while dimming unrelated ones. Edit sessions commit through the shared store so each session can be treated as one logical edit rather than a separate user action per keystroke.

## 7. Persistence and export

The board is designed to persist items and connections in Supabase. A 500ms-debounced save reads the latest board directly from the store when it runs and only upserts current item and connection rows. Item rows include nullable integer width and height values and a nullable real scale value; NULL retains the corresponding default dimension or a scale of 1.0 for legacy rows. Resize frames are excluded from saving while a resize is active, so only the completed width and height reach Supabase. It keeps all map-loading and stale-map guards so a transient empty or mismatched local state cannot write to another map, and it never deletes rows as part of background synchronization. Deletion is reserved for explicit user actions: card deletion removes its connections and item in the card handler, connection deletion removes the selected connection in the edge controls, and Markdown apply removes only the rows represented by cards or connections the user confirmed deleting. New cards receive UUID identifiers before they are saved, and the local board starts empty rather than containing placeholder seed identifiers. Upsert failures are checked individually; the complete Supabase error object is logged for diagnosis, the user sees a save-failure toast, and saving is halted for the remainder of the session so a rejected write cannot create a retry loop. Explicit deletion failures are logged and shown in the relevant action's toast without removing the local item. Undo restores rows in local state, and the next upsert writes them again so restored cards and connections survive a hard refresh. JSON export preserves the complete board state, and Markdown export produces one heading per item with metadata, description, and outgoing connection bullets. JSON import replaces the current board after a valid file is selected.

## 8. Multiple maps

The board supports multiple independent maps. Each map is a named container for its own set of cards and connections; switching maps loads that map's items and connections and clears the current canvas. Undo history resets on every map switch so Cmd+Z never crosses map boundaries.

A 240px collapsible sidebar on the left lists maps and folders as a nested tree. The sidebar header shows a map icon, the label "MAPS", and a very small version tag (injected from package.json at build time) beside it. At the root level, folders are shown first (alphabetically), followed by loose maps (maps with no folder). Folders expand and collapse with a chevron; expanded state is persisted to localStorage. Each nesting level is indented by 16px. The active map is highlighted; clicking a map switches to it. Clicking the already-active map is a no-op: the sidebar handler compares the clicked map id to the active map id and returns immediately without calling setActiveMap, so no canvas clearing, item replacement, or connection replacement occurs. This prevents double-clicking or repeated clicking of the active map from blanking the canvas. A "+ New map" button at the bottom creates a new root-level map with an inline-editable name, switches to it, and shows the empty-canvas prompt. A "+ New folder" button beside it creates a new root-level folder. Right-clicking a map offers Rename (inline edit) and Delete. Right-clicking a folder offers Rename, New map inside, New subfolder (hidden at the maximum nesting depth), and Delete folder. Deleting a map asks for confirmation and warns that all its cards and connections will be permanently removed. If the last remaining map is deleted, a new empty "My board" is created automatically so the user is never left without a map.

The active map id and the sidebar collapsed state are persisted to localStorage so the app reopens on the same map with the sidebar in the same position. On first load, if no maps exist yet, a default map named "My board" is created automatically. Switching maps clears the visible canvas while the selected map's rows load; persistence is paused during that transition so the temporary empty state cannot delete another map's cards or connections. The store's setActiveMap also guards against re-selecting the active map: when the incoming id equals the current active map id (and the call is not forced), it returns early without clearing items, connections, or history, so neither direct store calls nor the sidebar click handler can blank the canvas by reselecting the same map.

The "+ New item" button creates new cards at the center of the current viewport, converted from screen to flow coordinates, so a new card is always visible regardless of pan or zoom. Double-clicking an empty area of the canvas still creates a card at the clicked position. Pressing N creates a card at the center of the current viewport. Enter starts inline title editing on the selected card with its title selected. Escape clears the selected card or connection and closes the open card editor. Alt+L runs the Arrange auto-layout; if cards are selected it arranges only those cards, otherwise it arranges the whole board. With a card selected, Alt+1 applies normal styling, Alt+2 applies highlighted styling, Alt+3 applies muted styling, Alt+4 applies red styling, Alt+5 applies black styling, and Alt+0 resets the card to normal; each style change is one undo entry and these shortcuts do nothing inside text fields. Alt+6 marks all selected cards as todo, Alt+7 as done, Alt+8 as question, Alt+9 as important, and Alt+Shift+0 clears the status; the whole multi-card change is one undo entry. Alt+1-5 and Alt+0 (colour) also apply to all selected cards as one undo entry and one batched Supabase write, using the same multi-selection model. The card context menu exposes the same five styles with their matching Alt-key shortcuts and retains the Reset / Alt+0 action. With a card selected, plain Tab creates one new card 300px to the right at the same vertical position, using the free-position spiral to avoid every existing card, and creates a directed connection from the selected card to the new card. The new card becomes selected and starts inline title editing with its title fully selected, so typing immediately names it; pressing Tab again continues the chain from that new card. Tab is handled inside the inline title editor itself: the editor commits the typed text before dispatching a custom event that runs the same Tab navigation logic as the keyboard handler, so the title is never lost and Tab-Tab-Tab chains continuously without leaving the keyboard. Shift+Tab inside the editor likewise commits and dispatches, selecting the previous card. Each Tab creation stores the card, connection, and selection change as one undo entry. If the new card falls outside the visible canvas, the viewport pans to reveal it and focus is re-asserted on the inline title input after the pan animation completes, so typing is never lost to the canvas pane. The new card receives a 500ms accent-ring pulse that is purely visual and is not saved. The inline title editor also re-asserts focus if it is stolen within the first 300ms of mounting, so a setCenter pan triggered after Tab or Shift+Tab can never leave focus on the React Flow pane. Shift+Tab selects the parent card of the currently selected card — the source of the most recent incoming connection — and opens its inline title editor with the text selected, so Tab-Tab-Tab and Shift+Tab both work continuously without touching the mouse. If the selected card has no parent connection, Shift+Tab falls back to the selection history back-stack (capped at 20 cards) without slicing it, so repeated presses walk back through recently visited cards. Shift+Tab never creates anything; it pans only when the destination is outside the viewport and re-focuses the inline editor after the pan completes. Cmd/Ctrl+ArrowUp/Down/Left/Right selects the nearest card in that direction from the selected card's centre, ignoring candidates more than 45 degrees off-axis, and pans the viewport when the destination is off screen; if an inline editor is open, focus is re-asserted after the pan completes. Plain arrows nudge every selected card by 16px and Shift+Arrow nudges by 1px; all selected cards move by the same delta as one undo entry via the batched commitDragMany action. These nudges remain separate from directional selection. Alt+= (or Alt+Plus) scales every selected card up by 10%, Alt+- (or Alt+Minus) scales them down by 10%, and Alt+Shift+R resets selected cards to their default size. Scaling operates on all currently selected cards (the same multi-selection that align and distribute use); with no selection the shortcuts do nothing. Each scale step grows or shrinks both the card dimensions and the card's typography: a nullable `scale` field (real, NULL = 1.0, clamped 0.6–2.5) is multiplied by the factor, and the card root sets a `--card-scale` CSS variable that drives all card typography via calc() — title (13px), headings (14px/13px/12px), paragraphs and lists (12px), inline code (11px), tag chips and due-date badge (11px), line-height, list padding-left, and paragraph margins all scale proportionally so text grows with the card rather than sitting tiny inside a larger box. Drag-resizing a card changes only width and height and never touches scale, so manual resizing means "more room" (text unchanged) while Alt+= means "make this card bigger" (text grows). Each scale step also moves positions outward from or inward toward the selection's bounding-box centre by the same factor, so spacing grows with the cards and they do not start overlapping. With a single card selected only its size and scale change and its position is unaffected. Dimensions are clamped to the resizer's existing bounds: width 180–700px, height 92–800px, scale 0.6–2.5. If every selected card is already clamped at the limit, the operation is a no-op with no history entry. Alt+Shift+R sets width, height, and scale back to null (default size and default text size) for selected cards without changing positions. Each shortcut press creates exactly one undo entry and one batched Supabase update that writes width, height, scale, posX, and posY together. Cmd/Ctrl+M toggles the markdown panel even when focus is inside the markdown textarea. Opening focuses the textarea and places the cursor at the start; closing blurs the textarea and returns focus to the canvas. Collapsing the panel does not discard unapplied markdown edits: the textarea value remains in component state, the dirty indicator remains visible, and the text is restored when the panel is reopened. All shortcuts are handled by one global listener in the application shell that uses a dispatch table of typed bindings rather than an if-chain. Every binding matches on `event.code` (e.g. "Digit1", "KeyL", "ArrowUp") instead of `event.key`, so macOS Option-key and non-US keyboard layouts that produce different characters (Option+1 emits "¡", Option+L emits "¬") still fire the correct shortcut. Digit and scale bindings accept both keyboard rows: Alt+0-9 and Alt+Shift+0 accept `["Digit0", "Numpad0"]` through `["Digit9", "Numpad9"]`, Alt+= accepts `["Equal", "NumpadAdd"]`, and Alt+- accepts `["Minus", "NumpadSubtract"]`, so the numeric keypad fires the same shortcuts as the top row. The shortcuts modal continues to show the single friendly `display` string (e.g. "Alt+2") regardless of how many codes a binding accepts. Modifiers (alt, shift, meta, ctrl) are matched with exact equality — a binding requiring `alt:true` does not match when shift is also held, preventing the Alt+0 / Alt+Shift+0 collision. On Windows/Linux with Latin American, Spanish, and most non-US layouts, the right Alt key is AltGr, which the browser reports as `altKey:true` AND `ctrlKey:true`. The matcher detects AltGr via `event.getModifierState("AltGraph")` and, for Alt bindings only, ignores the spurious `ctrlKey` that AltGr sets — no binding uses Ctrl+Alt together, so this is safe. Non-Alt bindings still require an exact `ctrlKey` match. On startup in dev mode, the table asserts no two bindings share the same code+modifier combination and logs a console.error if they do. The Alt+0 binding is an intentional alias for Alt+1 — both map to the colourNormal action — and is noted in the bindings array so it is not mistaken for a duplicate.

Shortcuts are classified as GLOBAL or CANVAS-ONLY. GLOBAL shortcuts fire even when a text field has focus: all Alt combos (colour, status, scale, reset size, arrange, align, distribute), Cmd/Ctrl+Z undo, and Cmd/Ctrl+M markdown panel. CANVAS-ONLY shortcuts are skipped when an INPUT, TEXTAREA, or contenteditable element has focus: N, Shift+N, Tab, Shift+Tab, Enter, Escape, Delete/Backspace, bare Arrows, and Cmd/Ctrl+Arrows. Escape is canvas-scoped so it never clears canvas selection while the user is typing in a panel; instead, the markdown panel textarea, burst input, popup editor, and shortcuts modal each handle Escape explicitly with stopPropagation. Alt combos always call preventDefault so they never insert characters into a focused input. Inline title editor, burst input, and popup editor only stopPropagation on Enter and Escape — all other keys bubble to the window handler so Alt combos work while editing.

Escape follows an innermost-overlay-first pattern. The burst input, popup editor, and shortcuts modal each handle Escape with stopPropagation and close themselves. The markdown panel textarea handles Escape by blurring itself and returning focus to the canvas pane. If the window listener receives Escape (which only happens when no text field is focused, since Escape is canvas-scoped), it checks whether an inline editor is open: the first Escape commits the edit, exits the editor, keeps the card selected, and returns focus to the React Flow pane so canvas-scope shortcuts work immediately; a second Escape clears the selection. The listener calls preventDefault only when a shortcut fires, and does nothing when there is no active map. Existing Delete/Backspace connection deletion and Cmd/Ctrl+Z undo behavior are preserved. All creation paths are disabled when there is no active map: the button is visually disabled and the double-click handler returns early. The store's createItem, createConnection, and duplicateItem actions also return early with a console warning if called without an active map, preventing items with a null map_id from being created.

The canvas exposes keyboard shortcuts through a small circular "?" button in the bottom-right control cluster, styled to match the existing Tidy and zoom controls and marked nodrag and nopan so it never interferes with canvas panning or dragging. It sits to the left of the Tidy and Arrange buttons so it does not overlap the minimap or the bottom-left React Flow controls. Clicking the button, or pressing "?" (Shift+/), opens a centred modal listing every shortcut grouped by section. The modal's contents are generated from the same dispatch table that drives the keyboard handler, so the two can never drift out of sync. Each row shows the key combination on the left in a key-cap style and the description on the right. Escape or clicking the backdrop closes the modal. The "?" keybinding follows the existing keybinding guard pattern: it does not open when an input, textarea, or contenteditable element has focus, or when the popup editor or any other modal is open. The old always-visible hint strip has been removed entirely, so the sidebar and the Tidy / minimap controls are no longer overlapped.

New cards never land on top of existing ones. The placement helper spirals outward from the requested point until it finds a slot whose bounding box (including a 16px margin) does not overlap any existing card. Overlap checks use each item's actual persisted width and height, or the corresponding 240px and 92px defaults when values are NULL, while preserving the existing snap-to-grid spacing behavior. Duplicate uses the same spiral with the original card excluded from the collision set, offset 32px down-right from the original.

## 9. Authentication

MyMind uses Supabase email and password authentication. A sign-in and sign-up screen is shown when no session is present. Once authenticated, the full board is displayed. The top bar includes a sign-out button. On sign-out the local board state is cleared so no stale data from a previous user remains in the browser.

Each item and connection row is owned by the signed-in user through a `user_id` column that defaults to `auth.uid()`. Inserts do not send a user_id from the client; the database fills it automatically. Row level security is enabled on both tables with a single per-table policy restricting all operations to authenticated users who own the row. Email confirmation is disabled so new accounts can sign in immediately during development.

## 10. Folders

Maps can be organized into folders in the sidebar tree. Folders are stored in a dedicated `folders` table with a `parent_id` self-reference for nesting, owned by the signed-in user through `user_id` with the same RLS policy as maps. A map's folder is stored as `folder_id` on the maps table (nullable; null means the map sits at the root level). Deleting a folder sets its maps' `folder_id` to null at the database level via `ON DELETE SET NULL` — never cascade — so the database never silently deletes maps. The app handles map deletion explicitly after user confirmation.

Folders nest a maximum of 3 levels (root folder, child, grandchild). Depth is computed by walking the parent chain, and the "New subfolder" action is hidden on a level-3 folder so a fourth level is never offered.

Deleting a folder shows a confirmation dialog stating exactly what will be deleted: the folder name, the number of subfolders inside it, and the number of maps inside it (including maps in subfolders), e.g. "Delete 'Research'? This will also delete 2 subfolders and 5 maps, including all their cards and connections." On confirm, the app deletes the maps (and their items and connections) explicitly first, then the subfolders, then the folder itself. If the active map was among those deleted, the app switches to the first remaining map, or creates a new "My board" if none remain.

## 11. Drag-and-drop organization

Maps and folders can be rearranged in the sidebar tree using native HTML5 drag-and-drop (no drag library). A map can be dropped into a folder or onto the root area to leave all folders (folder_id = null). A folder can be dropped into another folder or onto the root area.

Three rules are enforced during dragging: (1) the 3-level depth limit accounts for the dragged folder's entire subtree height, not just the target depth — a folder with children dropped into a level-2 folder is rejected if the combined depth would exceed 3; (2) a folder can never be dropped into itself or any of its own descendants — the app walks the target's parent chain and rejects the drop if the dragged folder appears in it; (3) rejected drops show no drop indicator and do nothing on release.

Visual feedback: the dragged row dims to 50% opacity; a valid folder target gets a highlighted blue background; the root drop area shows a 2px accent line at the bottom of the tree when a valid root drop is in progress; and hovering over a collapsed folder for 600ms auto-expands it so deeper drops are possible.

Persistence is optimistic: the store updates first (maps.folder_id or folders.parent_id), then the database write follows. If the write fails, the store reverts to the previous value and a toast appears. These moves do not enter the zundo undo history — sidebar organization is separate from canvas editing.

## 12. Markdown map panel

The top bar includes a Markdown toggle that opens a 360px collapsible right sidebar for the active map. The panel contains a full-height monospace textarea with no rendered preview, an Apply to canvas button, and a small filled dot beside MARKDOWN while edits are unsaved. Its collapsed state is saved in localStorage and restored on the next visit. The panel is disabled while a map is loading. Switching maps discards unapplied markdown text after the existing discard confirmation, then regenerates the panel from the newly selected map.

Smart paste converts website HTML into markdown at the cursor, preserving headings, bold text, lists, links, and fenced code blocks. The conversion removes scripts, styles, navigation, footer, header, sidebar, form, iframe, noscript, and horizontal rule content. Plain text is inserted unchanged when the clipboard has no HTML, when the plain flavor already resembles markdown (including Obsidian content), or when Shift is held to force plain-text paste. The pasted fragment replaces the current selection and uses the browser's native undo behavior; existing panel content is never parsed or reserialized.

The canvas serializes cards in creation order. Each card is written as a level-two heading, optional Tags and Due metadata lines, and the description exactly as markdown content. When applying markdown, a first non-empty single H1 in a card description is promoted to the item title and removed from the description only when the item title is empty or "Untitled"; an existing non-empty, non-"Untitled" title remains unchanged and the H1 is preserved. The id comment that maps a section back to its card is never shown in the textarea — it is held in a separate ordered array alongside the displayed text, so the mapping stays intact without visual noise. Cards have no connection entries in this format. Canvas edits regenerate the textarea live unless it currently has focus or contains unsaved edits, so typing is never interrupted by background updates. Regeneration clears the dirty flag and replaces the text with canonical output.

Markdown never reaches the canvas implicitly. Blur is intentionally inert, and the panel does not parse on map switching, unmounting, click-outside, or any other focus or lifecycle event. The dirty flag is set only by textarea onChange. An explicit click on Apply to canvas, or Cmd/Ctrl+S while the textarea is focused, is the only path that parses markdown and commits it.

Apply guards refuse to change the canvas while a map load is in progress or when the textarea is empty while the canvas has cards. In either case the panel is regenerated from the canvas and a visible toast explains that nothing was applied. Any apply that would delete one or more cards opens an in-app confirmation modal listing the affected titles. Cancel, Escape, or backdrop click leaves the dirty draft and canvas unchanged; Delete commits the change.

Markdown parsing is intentionally section-based rather than keystroke-based. On apply, the displayed text is split into sections and ids are re-attached by section index from the stored array: the section at index N gets the id at index N. Sections beyond the stored array are treated as new cards; a shorter section list means the trailing cards were deleted. A section with a recognized id updates that existing card's title, tags, due date, and description, preserving its position and connections. A section without an id creates a new card with a UUID and places it in the first free card position. Removing a section removes that card and its connections. Sections with malformed metadata or unknown/duplicate ids are skipped and cannot delete existing cards.

Because positional id matching breaks when sections are reordered, the panel detects swaps explicitly: if more than one section's title fails to match the title of the card whose id sits at that index, and the same set of titles is present in a different order, the apply is refused. A message — "Reordering cards in the markdown panel isn't supported yet — reorder was not applied." — is shown and the panel is regenerated from the canvas so nothing is destroyed.

A complete markdown apply is one canvas undo entry. Cmd/Ctrl+S applies while the textarea is focused; ordinary typing only marks the draft as unsaved. After a successful apply, the panel regenerates canonical output and clears the dirty state. Position, color, and connections are not serialized, so dragging a card does not alter the markdown. The panel uses the active map's existing persistence flow, and map loading prevents an apply from reaching the wrong map.

## 13. Multi-selection, align, and distribute

The canvas supports multi-selection of cards. Shift-clicking a card toggles it in or out of the current multi-selection; clicking without Shift replaces the selection with that single card. Cmd/Ctrl-click also adds or removes individual cards from the multi-selection. Shift+drag draws a marquee (selection box) on the canvas; any card the marquee touches is selected, using partial intersection mode rather than requiring full containment. The store tracks a `selectedNodeIds` array alongside the existing single `selectedNodeId`; when exactly one card is selected both stay in sync, and when multiple are selected `selectedNodeId` is null. A unified `getSelectedIds()` selector returns `selectedNodeIds` when non-empty, else `[selectedNodeId]` when set, else an empty array. Every keyboard handler in the application shell reads selection through this single selector, so colour (Alt+1-5), status (Alt+6-9), scale (Alt+=/-), reset size (Alt+Shift+R), arrange (Alt+L), align/distribute, delete, arrow nudge, Enter (edit), and Tab (create connected card) all apply to the same set of cards consistently. Actions that need a single card (Enter to edit, Tab to create a connected card) use `getSelectedIds()[0]`; actions that can apply to many (colour, status, scale, delete, nudge) apply to all selected cards with one undo entry and one batched Supabase write. React Flow's `onSelectionChange` keeps the store's `selectedNodeIds` in sync with the canvas's internal selection state, so marquee selection and Cmd/Ctrl-click multi-select populate the same array that align, distribute, and Alt+L arrange read from. Clicking empty canvas or pressing Escape clears both `selectedNodeId` and `selectedNodeIds`, so neither selection model retains stale state. Every keyboard handler no-ops cleanly (no history entry, no write) when the selection is empty. The visual selection ring applies to every card in `selectedNodeIds`.

Align and distribute are manual, deterministic operations — no layout engine. They operate on the currently multi-selected cards and write `posX`/`posY` only; width and height are never altered. Each card's real persisted size is used (`width ?? CARD_DEFAULT_W`, `height ?? CARD_DEFAULT_H`), so resized cards align and distribute correctly. Aligned positions are final and are not re-snapped to the grid.

Align requires two or more selected cards and offers six modes: left (all `posX` set to the minimum `posX`), right (all right edges set to the maximum `posX + width`), top (all `posY` set to the minimum `posY`), bottom (all bottom edges set to the maximum `posY + height`), center-h (all horizontal centres set to the mean of current horizontal centres), and center-v (all vertical centres set to the mean of current vertical centres). If no positions actually change, the operation is a no-op and creates no history entry.

Distribute requires three or more selected cards and operates on a horizontal or vertical axis. Cards are sorted by position along the axis, the first and last remain fixed, and the middle items are spaced so the gaps between adjacent edges are equal — not the centres, since card sizes vary. Total gap is `(last edge - first edge) - sum of all sizes`, divided by `count - 1`; each item is placed after the previous one plus that gap. If total gap is negative (items overlap), even spacing is still applied rather than bailing. If no positions change, the operation is a no-op with no history entry.

Both align and distribute create exactly one zundo history entry and one batched Supabase update, following the same pattern as Arrange. The keyboard shortcuts are: Alt+Shift+ArrowLeft aligns left, Alt+Shift+ArrowRight aligns right, Alt+Shift+ArrowUp aligns top, Alt+Shift+ArrowDown aligns bottom, Alt+Shift+H distributes horizontally, and Alt+Shift+V distributes vertically. They follow the existing Alt-handler pattern and are ignored when a text input or textarea has focus; Alt+L (Arrange) continues to work unchanged. The shortcuts appear in the hint bar and the full shortcuts dialog.

Dragging a card that is part of a multi-selection moves every selected card together. On drag stop, the canvas reads all currently selected nodes (plus the grabbed node, which may not be flagged selected) and commits each one's final position in a single batched store action, `commitDragMany`, rather than committing only the grabbed card. This produces one zundo history entry for the whole multi-node move, so a single Ctrl+Z restores all moved cards; the debounced persistence flow in the app shell then writes all moved cards in one batched Supabase upsert. The existing single-card `commitDrag` action is retained for other callers. Clicking a card that is already part of an active multi-selection no longer collapses the selection — Cmd/Ctrl-click and Shift-click are ignored by the single-select handler, and a plain click on a card that is already among a multi-selection leaves the selection intact instead of replacing it with just that card.

## 14. Paste-to-cards

Pasting onto the canvas creates one or more new cards from the clipboard. The canvas handles the paste only when no input, textarea, or contenteditable element is focused and no inline or popup editor is open; otherwise the browser's normal paste behavior is left untouched. Website HTML uses the same Smart Paste conversion as the Markdown panel: headings, emphasis, lists, links, and fenced code are converted to markdown, while scripts, styles, navigation, footer, header, sidebar, forms, iframes, noscript content, and horizontal-rule content are removed. Plain text is preserved when there is no HTML, when it already resembles markdown, or when Shift is held.

Card splitting uses this priority order: if the content contains H1 or H2 headings, each H1/H2 heading starts a card and its following markdown becomes that card's description; otherwise, top-level `- ` or `* ` bullets become cards, including their indented child content as descriptions; otherwise the first line becomes the title and remaining lines become the description. A single first line longer than 80 characters becomes description-only with an empty title, which renders as Untitled. Empty sections are ignored. At most 30 cards are created; when additional sections are skipped, a visible notice states the skipped count.

Cards are placed in a vertical column beginning at the current pointer position on the canvas, with a 24px vertical gap. Every requested position passes through the existing free-position search, using current card dimensions for collision checks. Pasted cards use the default dimensions by leaving width and height null, receive fresh `crypto.randomUUID()` ids, have no tags, due date, color, or connections, and retain the converted markdown as their raw descriptions.

The complete paste is one local history entry, so one Ctrl+Z removes every card from that paste. All cards are added to the existing debounced persistence flow together, producing one batched item upsert rather than one write per card. The created cards are selected after insertion; a single pasted card opens for editing, while a multi-card paste does not open an editor.

## 15. Burst entry

Burst entry is a persistent single-line input for rapidly creating cards without leaving the keyboard. Shift+N opens the burst input; the shortcut follows the existing keybinding pattern in the application shell and is ignored when an input, textarea, or contenteditable element has focus or when the popup editor is open. The existing plain N shortcut is unchanged.

The input floats near the bottom-centre of the canvas, above the canvas but below any modal. It is a single-line text field with the placeholder "Type a thought, press Enter" and autofocuses on open. A small live count of cards created in the current burst session is shown beside the input. The input carries the nodrag and nopan classes so canvas interactions do not fight it.

Enter creates a card from the current text, then clears the input and keeps it focused and open — this is the core of burst entry, not a one-shot dialog. Enter on an empty input closes the burst input as a second escape hatch. Escape closes immediately, discarding whatever is typed. Clicking outside also closes the input.

The typed text becomes the card title with an empty description. If the text is longer than 80 characters, it becomes the description instead and the title is left empty, rendering as Untitled — the same rule as paste-to-cards. Whitespace is trimmed; empty or whitespace-only submissions are ignored. When the burst input opens, a clear vertical column is found once and stored for the whole session. The candidate anchor starts at the viewport centre (converted to flow coordinates via screenToFlowPosition), offset upward to roughly 28% of the visible height so the burst input at the bottom does not cover it. A vertical strip one card-width wide, running from the anchor Y to the bottom of the visible viewport, is tested for intersection with any existing card. If the strip is blocked, the candidate X shifts right by (card width + 32) and tests again, up to 6 steps; then the same number of steps to the left of the original centre. The first clear strip becomes the anchor. If no strip is clear, the anchor is placed just below the bottom-most existing card within the viewport's X range. Each card goes directly below the previous one: previous Y plus previous height plus a 24px gap — no per-card free-space search is run, and overlap is never allowed because the column was verified clear at session start. If the running column reaches the bottom of the visible viewport, a new column starts to the right (current column X plus card width plus 32) back at the anchor Y, and the same strip test runs for that new column so the wrap does not land on existing cards either. After each card is created, if it would fall outside the visible viewport the canvas pans just enough to bring it into view; zoom is not changed and focus stays in the input. The new card is not opened for editing and canvas selection is not changed, so focus stays in the input. No connections are created between burst cards. findFreeCardPosition is unchanged from its original behaviour and is not called by burst entry at all.

Each card receives a fresh crypto.randomUUID() id. Each Enter is its own Supabase write and its own zundo history entry, so Ctrl+Z removes burst cards one at a time — unlike paste-to-cards, these are separate deliberate actions. Shift+N appears in the keyboard shortcut hint bar and the full shortcuts dialog.

## 16. Markdown file import

Foreign markdown files (.md, .markdown, .txt) can be imported as new cards. This is a one-way, lossy import that creates new cards — it does not restore edges, positions, colors, or any MyMind state. No merge or round-trip logic is built.

Three entry points are supported. (1) Dragging and dropping a markdown file onto the canvas shows a drag-over state — a dashed accent border and a centered "Drop markdown to create cards" label — while a file is dragged over it. Drags carrying no file are ignored so existing card dragging and marquee selection are unaffected. Non-markdown extensions are rejected with a toast: "Only .md, .markdown and .txt files can be imported." Only the first file is handled when several are dropped; a toast notes the rest were ignored. (2) Dragging and dropping a markdown file onto an open card popup editor replaces that card's body content instead of creating cards. A confirmation dialog asks "Replace the contents of this card?" with the file name; no preview dialog is shown for this path. (3) An "Import markdown" item in the top-bar file menu opens a normal file picker and runs the same flow as (1).

Parsing strips YAML frontmatter (--- ... --- at the very top) before splitting. If the frontmatter contains a `mymind:` key, the import is refused and a dialog explains: "This looks like a MyMind export. Re-importing it here would create duplicate cards and lose your connections. Round-trip import is not available yet." with a single Cancel button. Headings are counted by level (H1..H4); the default split level is the level with the most occurrences, ties breaking toward the shallower level. The document is split into sections at the chosen level. For each section the title is the heading text with inline markdown syntax stripped, and the body is everything until the next heading at the same or shallower level, kept as raw markdown — deeper headings stay inside the body untouched. Content before the first heading becomes its own card titled from the frontmatter `title` if present, otherwise the filename without extension. Body content is never rewritten, cleaned, or reformatted. Leading and trailing blank lines are trimmed from each body; sections whose title and body are both empty are dropped.

Before creating anything (entry points 1 and 3), a preview dialog shows the file name and total size in KB, a split-level selector (H1/H2/H3/H4) defaulting as above and showing only levels that occur in the file, the resulting card count, and a scrollable list of card titles in order. Changing the split level re-parses live. If the count exceeds 60, an inline warning reads "This will create N cards." Import and Cancel buttons are shown; nothing is created until Import is pressed.

Cards are created through the existing batch card-creation path so persistence, undo, and Supabase saving work exactly as they do for manually created cards — no new save path or direct Supabase call is written. The whole import is batched into one undo step so a single Ctrl+Z removes every imported card. Cards are laid out in a grid at the drop point (or viewport center for the menu entry): columns = ceil(sqrt(cardCount)), spacing derived from the default card size plus the existing gap constant. Dagre is not run because there are no edges to lay out. Cards use the default size, color, and status; no edges are created. Every imported card is left selected when done so Alt+L, align, and scale can be applied immediately. A toast on completion reads "Imported N cards from <filename>."



## 17. PDF export

The current map can be exported as a single-page US Letter PDF. A toolbar button with a FileDown icon sits next to the existing Export dropdown, labelled "PDF" with the tooltip "Export map as PDF (Alt+P)". The keyboard shortcut Alt+P (canvas-only tier, matching on `event.code === "KeyP"`) triggers the same export path. The shortcut appears in the "?" shortcuts modal under the Layout section via the dispatch table.

The export captures the React Flow viewport as a raster image and places it on a single Letter page (215.9 × 279.4mm), independent of the user's current pan or zoom. It computes bounds from all card positions using `getNodesBounds` and picks a raster size from the bounds' aspect ratio: the long edge targets 2400px, clamped so neither dimension exceeds 8000px (the canvas element limit). It then calls `getViewportForBounds` with a minZoom floor of 0.2, maxZoom 4, and a padding ratio of 0.1 (10% of the bounds, not pixels) to derive an export-only `{ x, y, zoom }` viewport — the live viewport is never read, so the export is deterministic regardless of where the user has scrolled or zoomed.

Export dialog: Alt+P and the PDF button no longer export immediately. They open a small dialog first with a checkbox (default ON) labelled "Include card contents as text pages" with help text "Adds every card's full text after the map image, so long cards aren't cut off." The checkbox state is persisted in localStorage under "mymind.pdfExport.includeAppendix". Export and Cancel buttons are shown. When unchecked, the export is exactly the previous behaviour — one page, nothing else changes.

Map page with badges: when the appendix is included, a small numbered badge is drawn on each card in the captured map image. The badge sits at the card's top-right corner, is small and high-contrast (dark background, white text). This is implemented by adding an "is-exporting-with-appendix" class to the React Flow wrapper during capture (alongside the existing "is-exporting" class) that reveals a badge element already rendered on each card but hidden by default via CSS. The badge number is set as a "data-number" attribute on the badge element before capture, and a CSS pseudo-element displays it via `content: attr(data-number)`. The capture pipeline itself is unchanged — no drawing onto the canvas after capture.

Reading order: card order is determined once and used for both the badges and the appendix. The algorithm builds the edge graph, finds root cards (those with no incoming edges), orders roots top-to-bottom then left-to-right by position, walks outgoing edges depth-first from each root ordering children top-to-bottom then left-to-right, visits each card exactly once (skipping already-visited cards so cycles do not recurse infinitely), and appends any never-reached card (isolated or in a cycle with no root) at the end in top-to-bottom, left-to-right order.

Appendix pages: the appendix starts on a new page after the map. It is rendered as real text via jsPDF — selectable and searchable, not captured images. For each card in reading order: a heading line "N. <card title>" (using "Untitled" if empty), then the card body rendered from its markdown — ATX headings become bold sized by level stepping down from just under the card-title size to body size, paragraphs are body text wrapped to the column, bullet and numbered lists are indented by nesting depth with a bullet glyph or the number using two-space nesting steps, task items render an empty box glyph for `- [ ]` and a checked box glyph for `- [x]`, bold and italic use the bold/italic font variants with markers stripped, inline code and fenced code blocks use courier with a light background band for fenced blocks and never wrap or reflow (clipped at the column edge), blockquotes are indented with a vertical rule, links print the text followed by the URL in parentheses smaller and muted, and horizontal rules render as a thin line. The codeMask helper is used so markdown syntax inside code blocks is printed literally. Then, if the card has any edges, a "Connections" block in smaller muted text with one line per edge: outgoing edges as "→ N. <target title> — <edge comment>" and incoming edges as "← N. <source title> — <edge comment>", omitting the dash and comment when an edge has no comment, using the target or source card's badge number. A thin separator rule follows, then the next card. Layout: Letter with 10mm margins, single text column, page breaks when the cursor passes the bottom margin, a card heading is never split from its first body line (if it would land within 20mm of the bottom, it starts on the next page), long cards flow across pages, and a right-aligned muted page-number footer appears on every appendix page.

The capture uses `html-to-image`'s `toPng` on the `.react-flow__viewport` element with `backgroundColor: '#ffffff'`, `pixelRatio: 2`, `cacheBust: true`, and inline width/height/transform styles that apply the export viewport. A filter excludes minimap, controls, panels, attribution, handles, resize controls, and selection rectangles from the image. If `toPng` rejects with a CSS/CORS/stylesheet error, it retries once with `skipFonts: true` before surfacing the failure to the user via a toast.

Before capture, node and edge selection is cleared so selection rings and the top-left drag dot do not appear in the export. A CSS class `is-exporting` is added to the React Flow wrapper during capture; CSS rules on that class hide the drag dot, resize handles, and the edge midpoint delete button. After capture, the class is removed and the previous selection is restored. The export button shows a lightweight "Exporting…" busy state while the capture is in progress, since large maps take 1–3 seconds.

The PDF is built with `jsPDF`: orientation is landscape when the image is wider than tall, portrait otherwise; page size is US Letter (215.9 × 279.4mm); the image is fit inside the page with a 10mm margin, preserving aspect ratio and centred on both axes. The filename is `MyMind_${mapName} ${dd-mm-yy} ${HH.MM}.pdf` (e.g. "MyMind_Strategy map 18-08-26 14.32.pdf"), using local time on a 24-hour clock. The map name is sanitised by stripping `/ \ : * ? " < > |` and collapsing runs of whitespace to a single space, falling back to "Map" when empty.

The export uses the measured React Flow nodes from `useReactFlow().getNodes()` (exposed via a window ref from Canvas), not Zustand state — React Flow v12 stores dimensions on `node.measured`, and `getNodesBounds` returns zero/NaN bounds without them. The export guards against invalid bounds, non-finite viewport values, and blank captures (dataUrl shorter than 5000 bytes or not starting with `data:image/png`), throwing a clear error instead of writing an empty PDF. Total raster pixels are clamped to 25,000,000 — pixelRatio drops to 1, then image dimensions scale down proportionally if still over — to avoid the browser silently returning a blank canvas past its area limit. The export never touches the live viewport, zoom, fitView, persistence, or any Supabase code.

## 18. Markdown fidelity

Card body markdown is stored and returned exactly as authored — byte-for-byte round trips. No path that touches a body normalizes, re-serializes, or round-trips it through the renderer. The serializers (serializeItems and serializeItemsForDisplay) write the description verbatim with only leading/trailing blank-line trimming; the previous stripIdComments pass that rewrote body content has been removed. The markdown parser (parseMarkdown) masks fenced (``` and ~~~) and 4-space-indented code blocks before splitting on ## headings, so a # or ## inside a code block is never interpreted as a heading or stripped from the body. A shared helper (src/lib/codeMask.ts) provides maskCodeBlocks / restoreCodeBlocks / withCodeMasking and is used everywhere line-based processing happens: the markdown parser, the paste handler, and the serializers.

Hard line breaks: the react-markdown plugin chain includes remark-breaks alongside remark-gfm in both the card preview (ItemNode) and the popup editor preview (PopupEditor), so single newlines render as line breaks. Multi-line blocks like address or palette lists display as authored, not collapsed into one paragraph.

List markers: Tailwind's preflight resets `list-style: none` on ul/ol, which stripped bullet and number glyphs from react-markdown's list output. Markers are restored for markdown-rendered content only — the app's own UI lists keep the reset. The card face (`.card-markdown-preview`) and the popup editor preview (`.md-render`) both get scoped CSS: ul uses `list-style: disc outside`, ol uses `list-style: decimal outside`, nested ul levels go circle then square, and ordered nesting keeps decimal. Padding-left is 1.25em (scaled by `--card-scale` on cards) so markers are visible and not clipped at the card's left edge. Task list items (`- [ ]` / `- [x]`) get `list-style: none` so they render only the checkbox, never a bullet plus a box. List item margins are zeroed so lists stay compact inside a card. Markers remain visible at small card widths because the padding scales with the card.

Code block safety: fenced and 4-space-indented code blocks are opaque. No transformation anywhere in the app alters their contents or interprets markdown syntax inside them. A # inside a code block is text. The paste handler, the markdown panel, and the import/export paths all use the shared code-mask helper to mask code regions before any line-based processing and restore them after.

H1 promotion is opt-in: a leading H1 in pasted or imported content is COPIED to the card title if the title is empty (or "Untitled"), and LEFT IN PLACE in the body. The previous behavior removed the H1 from the body, which destroyed documents that legitimately open with an H1. The H1 is never removed from the body.

Dual-flavour copy: when copying a card, a selection of cards, or the markdown panel contents, both clipboard flavours are written using the async Clipboard API with a ClipboardItem: text/plain carries the raw markdown verbatim, and text/html carries the rendered HTML for that same markdown, produced by the same react-markdown pipeline the cards use (renderToStaticMarkup with remark-gfm and remark-breaks), wrapped in a minimal inline-styled container so headings, lists, bold, italic, links, code blocks, and tables carry over into rich-text targets like Google Docs and Word. If ClipboardItem is unavailable, it falls back to plain-text-only via the legacy navigator.clipboard.writeText path, and does not throw if the async API is blocked. Multiple cards are joined with a blank line between each card's document; no --- separators are inserted. Copy is triggered by Cmd/Ctrl+C on the canvas (when no text field is focused) and via a Copy button in the card context menu.

Paste preference: in the smart paste handler, when the clipboard carries both text/plain and text/html, text/plain is preferred if it already looks like markdown — a line starting with #{1,6} plus a space, a line starting with -/*/+ plus a space, a fenced code block (``` or ~~~), a numbered list line, or [text](url). Turndown runs on the HTML only when the plain text does not look like markdown. This prevents double conversion producing escaped \* and \_ artifacts.

## 19. Markdown editor keyboard handling

The popup card editor's description textarea behaves like a lightweight markdown editor. It remains a plain textarea — the raw markdown stays the source of truth. No rich-text or WYSIWYG editor library is introduced. All keyboard handling operates on the textarea's value and selection through pure functions in src/lib/markdownEditing.ts, which take { value, selectionStart, selectionEnd } and return the same shape. Every change goes through the existing updateItem path so undo, autosave, and persistence keep working untouched.

List continuation (Enter): pressing Enter detects the current line's list prefix — `- `, `* `, `+ `, `1. ` (any number), `- [ ] `, `- [x] `, and any leading indentation before it. Enter on a line with content after the prefix inserts a new line with the same indentation and an equivalent prefix; numbered lists increment, and task items always continue as `- [ ] ` (never `- [x] `). Enter on a line whose prefix is present but content is empty removes the prefix (outdenting one level first if indented, otherwise clearing it entirely) — the standard "Enter twice ends the list" behaviour. Enter inside a blockquote line (`> `) continues the `> ` with the same empty-line termination rule. Enter inside a fenced or indented code block inserts a plain newline preserving the current indentation; no list logic runs inside code.

Indent / outdent (Tab / Shift+Tab): on a list line, Tab indents by two spaces and Shift+Tab outdents by two, never past column 0; ordered lists are renumbered after the change. With a multi-line selection, every line in the selection is indented or outdented and the selection keeps covering the same lines. On a non-list line with a collapsed cursor, Tab inserts two spaces. Tab never moves focus out of the textarea — preventDefault is called, and Escape remains the way to leave the editor. Escape still closes the popup as before.

Inline formatting (wrap or unwrap the selection; toggle): Cmd/Ctrl+B toggles **bold**, Cmd/Ctrl+I toggles *italic*, Cmd/Ctrl+Shift+X toggles ~~strikethrough~~, Cmd/Ctrl+E toggles `code`, and Cmd/Ctrl+K inserts [selection](url) with the cursor placed inside the empty parens (the clipboard is not read — if it cannot be read synchronously the URL is left empty; this is not async). These are inline operations: if the trimmed selection spans multiple lines (contains a newline), the toggle does nothing at all — the value and selection are left untouched — because markdown inline syntax cannot span lines and wrapping a multi-line block would produce broken markup. With no selection, the paired markers are inserted and the cursor is placed between them. Before wrapping, the selection is shrunk inward past any leading and trailing whitespace (including newlines) so that only the trimmed core is wrapped; the whitespace stays outside the markers, preventing `**word **` artifacts that markdown would not render. If the selection is entirely whitespace, nothing happens. The same trimming is applied when detecting an existing wrap for the unwrap/toggle path, so toggling off still works on a selection that picked up a trailing space. After wrapping, the selection covers the trimmed text plus its new markers.

Block formatting (applies to every line touched by the selection): Cmd/Ctrl+1 through Cmd/Ctrl+6 set the line's heading level, replacing any existing leading #'s; pressing the same level again removes the heading. Cmd/Ctrl+Shift+7 toggles ordered list, Cmd/Ctrl+Shift+8 toggles bullet list, Cmd/Ctrl+Shift+9 toggles blockquote, Cmd/Ctrl+Shift+Enter toggles a task item (`- [ ] `) on the current line, and Cmd/Ctrl+Enter toggles the checkbox state between `- [ ] ` and `- [x] ` on the current task line. Toggling off restores the line to plain text. Heading shortcuts accept both Digit and Numpad keys.

Conflict check: all existing canvas shortcuts continue to work exactly as before. The textarea's keydown handler calls stopPropagation on every handled key so canvas-scope shortcuts never fire while the textarea has focus. The existing tiered guard (canvas-scope bindings are skipped when an INPUT, TEXTAREA, or contenteditable element has focus) already covers the case, and the textarea's explicit stopPropagation is a second layer. Cmd/Ctrl+E and Cmd/Ctrl+K in particular are won by the textarea while it has focus. All letter and digit matching uses event.code, not event.key, and the numpad digits are accepted for the heading shortcuts. Every digit-based binding — Cmd/Ctrl+1-6 for headings and Cmd/Ctrl+Shift+7/8/9 for lists/blockquote — matches on event.code (Digit1-Digit6, Digit7-Digit9, plus Numpad7-Numpad9), never on event.key, so Shift+digit combos that produce symbols (Shift+7 = '&', Shift+8 = '*', Shift+9 = '(') still fire correctly. Temporary console logging is in place to diagnose why the bullet list, ordered list, and blockquote toggles have no effect: the keydown handler logs { code, key, metaKey, ctrlKey, shiftKey, altKey } at the top; the three block toggle functions log their entry state and return value; and the toolbar button handler logs the action name and whether the returned value differs from the input. The logging will be removed once the failing stage is identified.

Task checkboxes in the rendered card: task list items rendered on the card face are real checkboxes. Clicking a checkbox toggles the underlying `- [ ]` / `- [x]` in the body through the normal updateItem path and saves. Clicking a checkbox does not start a card drag or open the editor — the click handler calls stopPropagation and preventDefault. The checkbox renderer assigns each task item a stable index at render time by counting task-list-item nodes in document order, so the correct line is toggled even when non-task list items are interleaved.

Expand / collapse toggle: the popup editor has an expand/collapse button in its header row, left of the close control. It uses the lucide-react Maximize2 icon when collapsed and Minimize2 when expanded, with a tooltip reading "Expand editor" or "Collapse editor". Collapsed is exactly the current size (360px wide, max 70vh tall, anchored beside the card). Expanded is 95vw × 92vh centered in the viewport with a max-width of 1400px so it does not stretch absurdly on wide monitors; on viewports under 640px wide it uses 96vw × 94vh with no max-width. The textarea fills the available height in both states via flex so the header stays pinned and the textarea takes the remaining space. The size change animates with a ~150ms CSS transition with no layout jump. Toggling preserves the textarea's selectionStart, selectionEnd, and scrollTop — they are restored after the resize and focus stays in the textarea. The expanded state is persisted in localStorage under "mymind.popupEditor.expanded" and applied when the popup opens, so it stays expanded across cards and across sessions until toggled back. Alt+Enter toggles expand/collapse while the popup editor is open, matching on event.code "Enter" and "NumpadEnter" with altKey (not event.key). Escape keeps its current behaviour: it closes the popup in one press whether expanded or not. The Alt+Enter binding appears in the display-only "Markdown editing" group in the "?" shortcuts modal.

Formatting toolbar: the popup editor has a single horizontal toolbar row directly above the textarea, inside the popup. It is subtle — buttons have no borders, transparent backgrounds, and muted icon color that goes full-strength on hover with a light rounded hover background. A thin divider line separates the toolbar from the textarea. Buttons are icon-only, 28x28, using lucide-react icons, with a native title tooltip showing the action name and its keyboard shortcut (e.g. "Bold (Cmd+B)") using the platform-correct modifier symbol. Buttons are grouped with a small gap and a faint vertical divider between groups. Group 1 (headings): Heading1, Heading2, Heading3. Group 2 (inline): Bold, Italic, Strikethrough, Code, Link. Group 3 (blocks): Bullet list, Numbered list, Checklist, Blockquote. Every button calls exactly the same pure function in src/lib/markdownEditing.ts that the corresponding keyboard shortcut calls — no duplicated editing logic. Buttons act on the current selection in the textarea, using onMouseDown with preventDefault so the textarea never loses focus and the selection is not cleared before the handler runs. After any button action, focus returns to the textarea and the selection the editing function returned is restored. A button renders in an active/highlighted state when the cursor or selection is currently inside that formatting — e.g. the Bold button is active when the caret sits inside **...**, the H2 button is active on a line starting with ##. Clicking an active button removes the formatting, matching the existing toggle behaviour. Nothing is disabled; if a selection is entirely whitespace the underlying function already no-ops. The toolbar stays visible in both the collapsed and expanded popup states. Active-state detection uses dedicated pure functions (isInlineActive, isHeadingActive, isBulletListActive, isOrderedListActive, isTaskItemActive, isBlockquoteActive, isLinkActive) added to src/lib/markdownEditing.ts, which inspect the textarea value and selection to determine whether each format is currently applied at the cursor or around the selection.

Discoverability: every new binding is listed in the "?" shortcuts modal under a new "Markdown editing" group. The entries are display-only — they are not added to the matchBinding dispatch table (which would create duplicate code+modifier entries and collide with existing bindings like Cmd/Ctrl+B for sidebar toggle). Instead, a separate displayOnlyShortcuts array feeds the modal's section generator, so the modal and the keyboard handler cannot drift out of sync.

## 20. Map and folder search

The maps sidebar has a search box pinned at the top, above the folder/map list, so it stays visible while the list scrolls beneath it. It spans the full width of the sidebar with the sidebar's existing horizontal padding. A muted lucide-react Search icon sits inside the field on the left, and the placeholder reads "Search maps and folders". A clear button (lucide X) appears on the right only when there is text in the field.

Filtering is case-insensitive and accent-insensitive: both the query and the target name are normalized with String.normalize('NFD') and stripped of combining marks, so "diseno" matches "diseño". Matching is a substring match against map names and folder names only — card contents, descriptions, and tags are never searched.

A folder is shown if its own name matches the query, or if any map inside it (including maps in subfolders) matches. When a folder is shown only because of its children, only the matching maps inside it are shown — not all of them. Folders that match by name show all their maps. Every folder that has a visible match is auto-expanded while a query is active, so results are never hidden behind a collapsed folder. When the query is cleared, the expansion state the user had before searching is restored — nothing is left artificially expanded. Filtering is display-only: it never modifies, reorders, moves, or deletes maps or folders.

When nothing matches, the list area shows muted centered text "No maps or folders match '<query>'" with a "Clear search" button beneath it.

The search field is a normal text input. Escape while the field is focused clears the query if there is one, and blurs the field if it is already empty. It does not close the sidebar or trigger any canvas shortcut. The existing tiered keyboard guard treats it as a field (INPUT tag), so bare letter shortcuts (T/F/G/C/E) do not fire while typing in it. No global focus shortcut is added for the field.

Filtering is debounced by approximately 120ms so typing stays smooth on large lists, but the input itself is fully controlled and responsive — every keystroke updates the input value immediately, and only the filtering computation is deferred.

Card content search: in addition to map and folder names, the sidebar search queries card titles and bodies across all of the user's maps via Supabase. Card matching MUST query the database — cards for maps that are not currently loaded do not exist in client state and cannot be filtered in memory. The query is debounced by approximately 300ms and requires at least 2 characters before it runs. A single Supabase query is issued against the items table, scoped to the current user by row-level security, matching title OR description with a case-insensitive substring (ilike with wildcards on both sides). The %, _, and \ characters in the user's input are escaped before the pattern is built so they match literally. Results are limited to 50 rows, selecting only card id, map id, title, and enough body text for a snippet. The map name and folder for each hit are looked up from the already-loaded maps and folders so results can be grouped. NOTE: the Supabase ilike match is NOT accent-insensitive unless the database has the unaccent extension enabled; no migration is added for this now. The client-side name filter above remains accent-insensitive via normalize(), but card body and title matching relies on plain ilike.

Race guarding: each query increments a request counter. When a newer query has been typed, in-flight responses are ignored by comparing the counter, so results never arrive out of order and overwrite newer ones. On query error, a muted inline "Couldn't search card contents" line appears under the name results; the name filtering itself is never affected and keeps working instantly and client-side.

Results list: while a query is active, the sidebar shows two sections. First, "Maps & folders" — the existing name filter, unchanged, with a count. Second, "In cards" — the Supabase hits, grouped by map name, each group showing its folder as muted secondary text. Each card result shows the card title (or "Untitled" when empty) and a one-line snippet of the body around the first match, with the matched substring highlighted. The snippet is truncated with ellipses on both sides as needed and markdown syntax is stripped so it reads as plain text. Each section shows a count; a section with no results is omitted rather than showing an empty header. While the card query is in flight, a subtle loading line appears in the "In cards" section only; the name results appear immediately.

Clicking a card result: if the card is in the currently open map, it is selected and the viewport pans to centre it without changing zoom. If it is in a different map, that map is loaded first via the existing map-loading path (setActiveMap), then the card is selected and centred once loading completes, respecting the loadedMapIdRef guard — no new loading path is written. The target card receives a brief pulse/highlight for approximately 1.5s so it is findable on arrival. The search query is cleared after navigating. This pass is strictly read-only: no card or map data is modified, written, or deleted.

## 21. Focus mode

Focus mode is a display-only view that dims cards and edges based on their graph distance from a selected card, so the user can visually trace a neighbourhood without losing the surrounding context. It never moves, modifies, saves, or deletes anything.

Activation: Alt+F on the canvas with exactly one card selected toggles focus mode on and off. The bare F key was already taken (fit to view), so Alt+F was chosen instead. Focus mode also exits on Escape, clicking empty canvas, or selecting a different card — which re-focuses on that card rather than exiting. Focus mode is not persisted: it never survives a reload or a map switch.

The walk: on activation, a breadth-first search radiates outward from the focused card along edges, treating edges as undirected, and records each card's hop distance. The focused card is distance 0, its direct neighbours 1, and so on. Cards not reachable at all get Infinity. The BFS guards against cycles by never revisiting a card already assigned a distance.

Depth: starts at depth 1 (the focused card plus its direct neighbours). ] increases depth by 1, [ decreases it (minimum 1). Depth cannot increase past the maximum distance actually present in the graph, at which point every connected card is already visible.

Rendering: cards at distance less than or equal to depth are fully opaque and behave normally. Cards beyond depth (including unreachable ones) are dimmed to opacity 0.12 and given pointer-events none so they cannot be clicked or dragged by accident. Edges are fully opaque only when both endpoints are within depth; otherwise they are dimmed to the same 0.12, along with their comment labels and leader lines — an edge label never stays bright over a dimmed edge. Opacity transitions over approximately 150ms so widening and narrowing reads as a change rather than a flicker. This is applied by adding classes to the existing card and edge elements; nothing is unmounted, no node data or positions are touched.

Indicator: while focus mode is active, a small pill appears at the top center of the canvas reading "Focus: <card title> · depth <n> · <visible>/<total> cards". It has an X to exit, and the depth number has small minus and plus controls that do the same as [ and ].

Interaction while active: dimmed cards are inert — not selectable, not draggable, and excluded from marquee selection. Visible cards behave completely normally: drag, edit, connect, delete. Alt+L (arrange), align, distribute, and scale operate only on visible cards while focus mode is active, never on dimmed ones. Deleting the focused card exits focus mode.

Discoverability: the Alt+F, ], and [ bindings are registered in the dispatch table and appear in the ? shortcuts modal under a new "Focus mode" group.

Viewport: on entering focus mode, the current viewport (x, y, zoom) is saved in memory only — never to localStorage, never interacting with the existing per-map viewport persistence. The viewport then animates (over approximately 300ms, maxZoom 1.5, padding 0.2) to fit only the currently visible (non-dimmed) cards, so a single isolated card does not blow up absurdly. Whenever depth changes with ] or [, the viewport re-fits to the newly visible set with the same animation. Selecting a different card while focus mode is active re-focuses and re-fits to the new neighbourhood, but does NOT overwrite the stored original viewport. On exit — by Alt+F, Escape, or clicking empty canvas — the saved viewport is restored with the same approximately 300ms animation, putting the user back exactly where they were when focus mode began. If the user pans or zooms manually while focus mode is active, the viewport is left alone; only enter, depth change, re-focus, and exit cause programmatic viewport changes.

## 22. Map favorites

Maps can be marked as favorites so they are reachable quickly regardless of which folder they live in. A boolean column `is_favorite` (NOT NULL, default false) is added to the maps table. No backfill is needed because the column defaults to false; no existing column is altered, renamed, or dropped, and the cards and edges tables are not touched.

Toggling: each map row in the sidebar shows a lucide Star icon. The star is outlined when the map is not favorited and filled (amber) when it is. Non-favorite stars are visible on hover; favorite stars are always visible. Clicking the star toggles the favorite state and writes to Supabase immediately. The click calls stopPropagation so it never opens the map. The update is optimistic: the UI flips first, then the database write follows. If the write fails, the icon reverts and a brief error toast appears, so the UI never shows a state that was not saved. The map's existing context menu also offers the toggle as "Add to favorites" or "Remove from favorites" (showing the current state).

Favorites section: a "Favorites" section is pinned at the very top of the sidebar, above the folder list and below the search box. It lists every favorited map, flat, regardless of which folder it lives in, sorted by name. Each row shows the map name plus its folder name as muted secondary text, so two similarly-named maps in different folders are distinguishable. The section is collapsible, and its collapsed state persists in localStorage under a MyMind-namespaced key ("mymind.favoritesCollapsed"). The section is hidden entirely when there are no favorites — no empty state, no header. A favorited map appears in BOTH the Favorites section and its normal folder position; favoriting never removes a map from its folder.

Interaction with search: while a search query is active, the Favorites section is filtered by the same accent-insensitive name match as everything else, and hidden if nothing in it matches. Unstarring a map removes it from the Favorites section immediately, with no reload and no change to its folder position.

## 23. Command palette

A command palette provides a searchable, keyboard-driven way to discover and run any canvas action. It is opened with Cmd/Ctrl+K (matching on `event.code === "KeyK"`) and is also reachable via a small "⌘K" hint button placed unobtrusively on the canvas above the Tidy button. The hint button uses the platform-correct modifier symbol and dispatches the same `mymind:open-command-palette` event the keyboard handler uses.

The palette does not open while a text field (INPUT, TEXTAREA, or contenteditable) has focus — the popup editor textarea already binds Cmd+K for links, and the sidebar search is a field. It follows the existing tiered guard: the Cmd+K binding is registered as canvas-scope, so it is skipped when typing in a field, and the palette's own keydown listener applies the same check before opening. It also does not open when another modal is already open, using the same `mymind:modal-state` coordination the shortcuts modal uses.

Source of truth: the command list is built by reading the existing keyboard dispatch table (`bindings` in keyboardBindings.ts) plus the display-only `displayOnlyShortcuts` array. No second hardcoded command list is maintained. A new shortcut added to the dispatch table appears in the palette automatically, exactly as it already appears in the `?` shortcuts modal. The display-only "Markdown editing" entries are included in the list but marked as editor-only and hidden when the palette is opened from the canvas, since they are not runnable from the canvas.

Appearance: the palette is a centered modal near the top of the viewport (approximately 12vh from the top), approximately 560px wide, with a backdrop. A search input sits at the top with the placeholder "Type a command…". Results list below, max approximately 400px tall and scrollable. Each row shows the action name on the left and its keyboard shortcut on the right in muted monospace, using the platform-correct modifier symbols. Rows are grouped under their dispatch-table section headers (Creating, Editing, Layout, Focus mode, etc.) in the same order the `?` modal uses. The selected row is highlighted. The empty state reads "No commands match '<query>'".

Matching is case- and accent-insensitive subsequence matching on the action name, so "arr" matches "Arrange" and "expdf" matches "Export as PDF". Matched characters are highlighted within each name. Results are ranked: exact prefix matches above word-boundary matches above contiguous mid-word matches above scattered subsequence matches. With an empty query, every command is shown, grouped.

Keyboard: Up/Down move the selection, wrapping at the ends. Enter runs the selected command and closes the palette. The first result is selected by default so Enter works immediately. Typing always goes to the search field; the field keeps focus throughout — arrow navigation does not blur it.

Running a command dispatches through the SAME `runAction` path the keyboard shortcuts use. The palette closes BEFORE running, so actions that open a dialog (PDF export) or need canvas focus behave normally. The palette dispatches a `mymind:run-action` CustomEvent carrying the action name; the `KeyboardShortcuts` effect listens for it and calls `runAction` directly — no duplicated logic. Commands that require a selection (align, distribute, scale, focus mode, edit, connect, tab) are shown but disabled, with muted styling and a short reason on the right such as "needs a selection" instead of the shortcut. Enter on a disabled row does nothing.

Discoverability: the Cmd/Ctrl+K binding is registered in the dispatch table so it lists in the `?` shortcuts modal under the Layout section. The "⌘K" hint button on the canvas opens the palette for users who never find the shortcut.

## 24. Typed cards

Cards have a data type that is stored in the database and will later drive graph queries. A `card_type` text column (NOT NULL, default 'note') is added to the items table via migration. Allowed values: 'note', 'decision', 'option', 'assumption', 'risk', 'evidence'. A CHECK constraint enforces the allowed values. Every existing card becomes 'note' via the default, so existing cards look and behave exactly as they do today — 'note' is the current appearance, unchanged. No existing column is altered, renamed, or dropped.

The six types and their visual shapes:

  note        Default. Square corners, current styling. No icon, no accent bar.
  decision    Cut corners (clip-path octagon-ish), heavier border. lucide GitFork icon. Accent: amber.
  option      Fully rounded corners (~18px). lucide CircleDot icon. Accent: blue.
  assumption  Pill-like — very large border radius (~28px) plus a DASHED border, signalling "unverified". lucide HelpCircle icon. Accent: violet.
  risk        Cut top-left and bottom-right corners only, solid heavier border. lucide AlertTriangle icon. Accent: red.
  evidence    Square corners with a folded top-right corner effect (CSS pseudo-element). lucide FileText icon. Accent: green.

Rendering: no literal diamonds, circles or ellipses are used — markdown text inside them would be unreadable. Only silhouette cues as specified above. Each non-note type shows its icon in the card header next to the title, and a 3px accent bar down the left edge in the type colour. The type accent does not conflict with the existing colour markers (Alt+1-5): colour markers control the card background; the type accent stays on the left bar and icon only. Type styling survives focus mode dimming, PDF capture, and the is-exporting class. The card body layout is identical across all types — same padding, same text area. Only the frame changes.

Setting the type: Alt+Shift+1 through Alt+Shift+6 set the type on selected cards, in the order listed above (1 = note, 6 = evidence). Both Digit and Numpad variants are matched. The bindings are registered in the dispatch table under a new "Card type" section so they appear in the `?` shortcuts modal and the command palette. A "Type" submenu is added to the card context menu listing all six types with their icons and a tick on the current one. The type applies to every selected card at once and goes through the existing card-update path so undo/redo and persistence work unchanged.

PDF appendix: in the text appendix, each card's heading is prefixed with its type when it is not 'note', e.g. "3. [Decision] Choose hosting provider".

This pass stores and displays the type only. No edge types, graph queries, filtering by type, or assumption collapse behaviour are added yet.

## 25. Duplicate map

A map can be duplicated from its right-click context menu in the sidebar. A "Duplicate" item is placed directly under "Rename", with a lucide Copy icon. Clicking it creates a complete copy of the map — the map row, every card, and every connection — without touching the original in any way.

Naming: the copy is named "<original name> copy". If that name already exists in the same folder, the name becomes "<original name> copy 2", then "copy 3", and so on. Name uniqueness is checked against maps in the same folder only, not across the entire workspace.

What is copied: the map row is copied with the same folder and settings, except `is_favorite` resets to false — a duplicate is never automatically a favorite. Every card is copied with its position, size, colour, status, card_type, title, body, tags, and due date preserved exactly. Every connection between those cards is copied with its comment/label preserved.

ID remapping: new UUIDs are generated for the new map and for every card. The originals are never reused. An old-id to new-id map is built as cards are created, then every connection's source and target are rewritten through it. Before writing, the code asserts that every connection's remapped source and target exist in the new card set. If any does not, the entire duplicate is aborted and an error is reported rather than writing a half-connected map.

Transactional behaviour: the map row is inserted first, then the cards, then the connections. If any step fails, whatever was already created is deleted so no partial map is left behind, and an error toast is shown. The source map is never modified — this is a read-then-insert operation.

After duplicating: the user stays on the currently open map. The app does not load or switch to the copy. The new map appears in the sidebar immediately, in the same folder, without a reload. A toast reads "Duplicated as '<new name>'". The menu item shows a busy spinner state while the operation runs, since large maps take a moment.
